日期：2026-11-19

## 基准场景 B0

Windows 11 x64，单屏 2560×1440，100% DPI，静态壁纸；
6 个 400×240 逻辑像素的面板，展示受控的中文文字、时钟和最多 24 个共享图标。
无照片、网页、网络组件；设置编辑器关闭；Release x64 构建，无调试器。
时钟默认分钟刷新，组件缓存先预热。此场景不是完整首版功能组合。

| 指标 | 初始挑战目标 | 口径 |
| --- | --- | --- |
| 稳态私有工作集 | ≤ 20 MiB | 6 面板进程树稳定采样 p95 |
| 稳态私有提交 | ≤ 40 MiB | 进程树 Private Bytes 稳定采样 p95 |
| 空闲 CPU | 接近 0，初始参考 ≤ 0.1% | 总 CPU 时间增量 / 墙钟 / 逻辑处理器数 |
| 常驻进程 | 1 个 | 编辑器关闭，无后台辅助 UI 进程 |
| 长稳 | 8 小时无持续增长趋势 | 私有提交、GDI / USER 句柄、GPU 与资源计数 |

初期不对 GPU / DWM 增量编造固定上限。P0 给出基线与窗口数量增长曲线，再设预算。
如实测超出，按设备、表面、缓存、运行时拆分定位，并记录预算修改理由。
不得仅更换计数器或清空工作集来宣布达标。

## 计数器

- Private Working Set：私有驻留物理页；不能用总 Working Set 冒充。
- Private Bytes / PrivateUsage：进程私有提交，不等于当前驻留物理内存。
- Working Set：含共享页，单独记录供解释。
- Dedicated / Shared GPU Memory：分别记录，不与 CPU 指标盲目相加。
- DWM 与系统提交：测开关面板前后的增量，并承认其他系统活动的噪声。
- handles、GDI / USER objects、线程数、缓存字节数和绘制次数用于定位增长。

记录整棵应用进程树。编辑器打开时的峰值单独报告；关闭后核实进程确实退出。
不能把 DWM 里的成本当作“免费”，也不能把共享显存全部当成独立物理内存再累加。

## 测量步骤

1. 记录 OS build、CPU、GPU / 驱动、内存、显示器、DPI、电源状态、构建提交。
2. 保持壁纸和后台应用一致，关闭应用记录 60 秒系统与 DWM 基线。
3. 启动应用，记录启动、图片解码、首次渲染的峰值。
4. 预热 60 秒；随后按 1 秒间隔采样 5 分钟，报告中位数、p95 和最大值。
5. 相同场景独立重复 3 次，同时保留未平滑的原始数据。
6. 拖动、缩放、主题与模式切换各重复 100 次，记录峰值与操作后恢复情况。
7. 执行 8 小时长稳；周期性采样，观察趋势并区分有界缓存预热与持续泄漏。
8. 对比同机同场景基线，归档脱敏报告，原始 ETL / dump 不进入 Git。

## 扩展场景

- B1：纯托盘隐藏；短期保留 / 长期回收资源策略对比。
- B2：1 / 6 / 12 面板增长曲线。
- B3：4K，150% / 200% DPI，双屏；单独报告，不能套用 B0 数字。
- B4：缓存玻璃 / Acrylic / 纯色；桌面与 HUD 分开。
- B5：50 / 500 / 5000 文件目录视图；可见项虚拟化和缓存上限。
- B6：Explorer 重启、显示器断开、睡眠恢复与设备重建。
- B7：设置打开 / 关闭后的峰值和资源回落。

## 资源设计规则

共享调度器与绘图设备；所有缓存有字节上限；图像按显示尺寸解码；
异步任务限制并发和响应大小；隐藏组件停止采样；无恒定帧率循环。
开机启动、天气、媒体与系统监测的增量必须独立测量。
