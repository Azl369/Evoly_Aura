# 玻璃材质与渲染策略

状态：方案设计，具体后端待 P0 验证。

## 两种材质路径

### 桌面态：缓存壁纸采样

获取用户所选屏幕的壁纸与布局方式，按面板位置计算采样区域。
尽量按较低分辨率解码或先缩小再模糊；保留少量边缘采样范围，避免裁剪边界伪影。
叠加色调、亮边及共享的小噪点纹理。缓存结果只在壁纸、面板位置、
尺寸、DPI 或主题变化时失效。

必须限制解码和中间图峰值。不能因为最终贴图小就忽略原始图片解码成本。
拖动时可使用已有低分辨率采样，结束后再精修，避免每次鼠标移动重做全图模糊。
缓存采用有界策略；不能永久保存所有历史位置的结果。

动态壁纸无法通过一次静态采样完整还原，首版使用明确的静态近似或纯色回退。

### HUD：系统材质候选

HUD 可能叠在其他应用上，需要时评估系统 Acrylic。
Win32 DWMWA_SYSTEMBACKDROP_TYPE 路径要求 Windows 11 Build 22621 或更新版本。
这一 API 的存在不保证任意 layered / child / 桌面挂载窗口组合都能直接工作。
必须验证具体窗口样式、合成路径和回退。

Mica 结合主题与壁纸生成背景，不等同于实时透视其他窗口的磨砂。
材质不可用、透明设置关闭或设备异常时保留清晰文字与可操作的实色背景。

## 资源结构

- 共享绘图设备、字体资源、常用画刷、图标缓存。
- 每面板按物理尺寸分配必要表面，窗口尺寸变化时回收旧尺寸资源。
- 不默认创建覆盖整块屏幕的透明渲染目标。
- 极近的面板是否合并绘制通过实验决定；合并后空白面积也要计入。
- 避免每层卡片分配独立模糊中间图；能共享的背景只计算一次。
- 图标按所需 DPI 尺寸提取，缩略图只为可见项生成。
- 设备丢失后统一重建设备相关资源，避免重复保留旧资源。

## 像素预算

32 位 BGRA 表面裸像素成本 = 物理宽 × 物理高 × 4 字节。

- 3840 × 2160 单份约 31.6 MiB。
- 400 × 240 单份约 0.37 MiB。
- 200% DPI 下逻辑宽高均翻倍，像素面积约为 100% DPI 的四倍。

这些只是裸像素，不包含对齐、驱动、缓冲份数、模糊中间图与 DWM 成本。
共享显存与进程提交有不同记账方式，不可把重叠计数器直接相加。

## 验证矩阵

桌面 / HUD、缓存玻璃 / 系统材质、单屏 / 多屏、100% / 150% / 200% DPI、
Windows 目标版本、深浅壁纸、透明关闭、Explorer 重启、设备恢复。
兼容失败需要有可用回退，再决定是否进入默认路径。
