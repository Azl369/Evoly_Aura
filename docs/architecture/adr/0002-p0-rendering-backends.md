# ADR-0002：P0 默认软件绘制，保留共享 GPU 实验路径

日期：2026-11-19
状态：接受为 P0 默认值；不代表完整 P0 或发布验收通过。

## 决策

默认使用 Direct2D 软件 DC render target + 每面板 32 位 DIB + UpdateLayeredWindow。
全部面板复用一个 DC render target、字体、壁纸采样图与四个系统图标。
每个窗口按物理尺寸持有自己的 DIB，不分配全屏透明画布。

保留独立的 composition 选项：共享 D3D11 / Direct2D / DirectComposition 设备与按窗表面。
该路径用于验证 Acrylic 和需要 GPU 的后续效果，不自动随应用常驻加载。

## 原因

本机探索性对照中，共享 GPU 路径的私有提交明显高于软件路径。
软件路径更接近低常驻内存的优先目标，静止时同样无需持续绘制。
最终数值、源码版本、二进制哈希和测量限制以性能报告为准。

此结论只针对当前设备、驱动、像素面积和内容；
不推论软件在动画、大照片、高 DPI、多屏下总是更优。

## 语义与代价

- 缓存玻璃来自静态壁纸，不实时采样 HUD 后面的其他应用。
- 软件后端选择 Acrylic 会实色回退，不伪装成实时模糊。
- GPU Acrylic 的 HRESULT 成功只表示 API 接受请求，仍需受控背景视觉验证。
- 软件 DC target 与进程堆可能保留高水位；隐藏释放面板表面不等于进程归零。
- GPU 后端隐藏时保留设备；对长期隐藏的设备卸载策略留到后续验证。
- 设备丢失、跨屏重采样、系统恢复和 Explorer 重启不因初次正常退出就视为通过。

## 复查触发条件

高 DPI / 4K / 多屏使软件复制成本明显增加；加入动画或媒体；
HUD 必须实时透出其他应用；驱动或 Windows 版本改变资源成本。
遇到上述情况应复测并修订此 ADR，不为保持结论而只比较某一个计数器。
